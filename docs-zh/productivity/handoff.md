## 它做什么

`handoff` 把你正在进行的这场对话压缩成一份**交接文档**：一个 markdown 文件，写到你操作系统的临时目录，而不是写进工作区，一个新的 [agent](https://www.aihero.dev/ai-coding-dictionary/agent)（代理）读它就能把这活儿接下去。

它给你的是**便携性**，不是压缩，所以这份 Skill 比它的名字窄。只有当工作必须*移动*的时候你才需要一个文件：换一个 [harness](https://www.aihero.dev/ai-coding-dictionary/harness)（运行外壳）、换一个目录、交给一位同事，或者分出一个你想另开的支线任务。没有东西要移动，你就不需要交接。留在 [session](https://www.aihero.dev/ai-coding-dictionary/session)（会话）里、`/clear`、一个 [subagent](https://www.aihero.dev/ai-coding-dictionary/subagent)（子代理）和 `/compact` 就覆盖了阶段收尾这个常见情形，而且 `/compact` 比这份 Skill 更常是正确答案。

## 什么时候找它

要输入 `/handoff` 才能调用它，agent 不会自己去找它。附一句说明，讲下一场 session 是干什么用的，这份 Skill 就照这个目的写文档。

触发场景有四个，也只有四个：

| 情形 | 为什么需要一个文件 |
| --- | --- |
| 换 harness（Claude → Codex） | 新 harness 看不见旧的 [context](https://www.aihero.dev/ai-coding-dictionary/context)（上下文） |
| 换到另一个目录或仓库 | 从一个原型目录出发是最常见的那种 |
| 把工作交给一位同事 | 他们需要一份读得懂的东西 |
| 在阶段中途发现一个值得另开的支线任务 | 你继续干；第二个 agent 接走那条支线 |

其余任何情形（同一个 harness、同一个目录，你 [grilling](https://www.aihero.dev/ai-coding-dictionary/grilling)（追问）完了要转入实现），用 `/compact`。在阶段边界上，[ask-matt](https://aihero.dev/skills-ask-matt) 有覆盖那五个选项的有序决策树。

## 分叉是人们跳过的那种用法

这份 Skill 的描述读起来像是 session 续接：写一份总结，在这里结束，在那里恢复。照这样读，它像一个更差的 `/compact`，于是人们跳过它。值得记住的其实是分叉那一种。你**留在自己的 session 里**，把攒下来的上下文复制一份交给第二个 agent，让它并行干活。

[prototype](https://aihero.dev/skills-prototype) 那条绕路走的就是这个。你正在一场设计对话的深处，撞上一个只有跑代码才能定下来的问题，而你不想把好不容易搭起来的那条主线花在找答案上。交给一场原型 session，拿到答案，把答案交回来，在原那条主线里引用它。工作来回跨了两次，你原来的对话始终是活的，而你什么都不必重新解释。

阶段边界上的五个选项里，有三个各自保住不同的东西：`/compact` 保住你的意图，`/clear` 什么都不保，`/handoff` 保住这份工作移动的能力。

## 什么会跟着走，什么不会

文档带着当前这条主线（正在做什么、为什么、下一步是什么），外加一节 **suggested skills**（建议的 Skill），点名下一个 agent 该去找谁。这份 Skill 在写文件之前会把密钥涂抹掉。

它刻意不带任何已经写下来的东西。文档用路径或 URL 引用 spec（规格说明）、计划、ADR、工单、commit 和 diff，从不复制它们。这让文件保持小，也让已经定下来的细节待在一个地方，而不是变成两份各走各的拷贝。

## 常见问题

**交接还是压缩？**
除非有东西要移动，否则用 `/compact`。留在同一个任务上是压缩，不是交接。harness 和目录都没变、你又得保持在环里的时候，阶段边界那棵决策树大多数时候都落在 `/compact`。`/handoff` 并不总结得更好。它的优势在于产出是一个文件，你能把它带到 `/compact` 到不了的地方。

**那 `/compact`、`/clear` 和 `/handoff` 到底差别在哪？**
它们各自保住的东西不同。`/compact` 压缩当前这份上下文，然后在一个新窗口里继续，所以你的意图活了下来。`/clear` 清空窗口，从零开始。当你身后的一切都可以丢弃时这是对的；如果并非如此，你做这个操作没法撤销。`/handoff` 写一个可携带的文件，所以工作能活过一次搬家。三者都把一个 **[一手来源](https://www.aihero.dev/ai-coding-dictionary/primary-source)**（如期发生的那场对话）变成一个 **[二手来源](https://www.aihero.dev/ai-coding-dictionary/secondary-source)**（它的一份摘要）。只有继续下去这一项不会这么做，这就是为什么你要先把它排除掉。

**我的交接文件跑哪去了？**
它去了临时目录，这是这份 Skill 被报告得最多的问题。这份 Skill 按 `$TMPDIR`、否则 `/tmp`（Windows 上是 `%TEMP%`）的顺序来解析它，但那些路径都很长。让它把路径回给你，在往下走之前把它存好。放临时目录是刻意的，因为一次交接是一份在途的文档，不是一个你要长期维护的产物。临时目录也不持久，下一个问题会解释这一点。

**我的交接在两场 session 之间消失了。**
有些环境会在 session 之间清空临时目录（Codex 是被报告的那种），一次重启也会把 `/private/tmp` 清空。如果下一场 session 不是在一小时内开始，或者要在另一个 harness 下开始，文件一写出来就自己把它复制到某个持久的地方。文档*指向*的东西同理：如果一次派发引用了临时目录里的其他文件，下一个 agent 就跟不过去。

**我到底怎么把它交给下一个 agent？**
开一场新 session，把它指向那个路径：读这个文件，然后继续。指向文件，别把摘要粘进一条 shell 命令。摘要里含有反引号或 `$(...)` 时，把它插值进 `claude "<summary>"` 会让 shell 把摘要搅乱。常见的结果是悄悄截断，而不是报错，于是新 agent 拿着一份不完整的要求开工，而没有任何东西提醒你。

**它和 `/branch`、`--fork-session` 或内置的 `/handoff` 是一回事吗？**
它们相似，但不相同。`/branch` 不是这里发布的一份 Skill；`/handoff` 是正式的名字。一次 fork 继承上下文的精确副本；这份 Skill 产出的是一份*有靶心的*压缩，指向一个说清楚的下一个任务，而且落在文件里。在 fork 能干的地方（同一台机器、同一个 harness、同一个目录），fork 更省事。当目的地是 fork 去不了的地方时，文件是更好的选择。

**什么时候该把它写进 `CLAUDE.md` 而不是这里？**
问自己下个月它还成立不成立。`CLAUDE.md` 是关于这个项目的常驻上下文，无论相关不相关都会加载进每一场 session。一次交接讲的是正在进行的某一件事，那件事落地之后它就毫无用处。如果你在一遍遍重新解释同一个事实，它属于 `CLAUDE.md`。一件干到一半的任务属于一次交接。

**它记的是做了什么，不是为什么。**
这是一条公允的批评，人们常提。两件事能帮忙。一是把理由一起传过去（告诉它下一场 session 是干什么用的），这样这份 Skill 保住的就是与*那个*目的相关的推理，而不是把它抹平。二是留意那些 session 里从没验证过却说得很有把握的断言，比如"X 还没建""Y 做完了"。下一个 agent 会信任这份文档而不去复查它，于是一个当成事实写下来的信念，就成了其后一切的一个假前提。交出去之前先读一遍这份文档，凡是你只是假设过的，都给它降级。

**为什么它是一份 Skill，而不是一个 slash command（斜杠命令）？**
两种都行；它们适合不同情形。作为一份 Skill，它和这里的其余一切走同一条安装路径分发和更新，这让它便于分享。真正阻止 agent 自己触发它的，是它的 frontmatter，不是它的机制。

## 有效的话应该是这样

- 文档只占对话的一小部分，而 spec、工单和 diff 在里面以路径和 URL 出现，不是以复制过来的正文出现。
- 你能冷读它：不打开原来那场 session，也知道下一步做什么。
- 新 agent 一上来就开始干活，而不是请你重新解释一遍设置。
- 分叉那种情形下，你回头时原来那场 session 没有任何变化。
- 建议 Skill 那一节点名的是你自己本来会去用的那份 Skill。
- 里面没有任何密钥、令牌或密码。

## 它在整体中的位置

`handoff` 是一个**随时可以拿起来用的独立 Skill**。它工作在 session 与 session 之间，而不是某条构建链里面。它很窄，你在阶段边界上用到它的次数会比另外四个选项少。它最靠近的邻居是 [prototype](https://aihero.dev/skills-prototype)，因为一个原型住在自己的目录里，而那一去一回的往返正是这份 Skill 要做的动作。当你在一个边界上拿不准该继续、该 `/clear`、该交接、该委派还是该 `/compact` 时，[ask-matt](https://aihero.dev/skills-ask-matt) 有把那五个排好序的那棵树，并在这套 Skill 的其余部分之间给你路由。
