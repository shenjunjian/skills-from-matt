## 它做什么

`teach` 把你运行它的那个目录变成一个常驻的教学工作区，用一门门简短、自成一体的 HTML 课，跨多场 [session](https://www.aihero.dev/ai-coding-dictionary/session)（会话）教你一个主题。

它不靠 [model](https://www.aihero.dev/ai-coding-dictionary/model)（模型）已经知道的东西来教。它把 **[参数化知识](https://www.aihero.dev/ai-coding-dictionary/parametric-knowledge)** 当作不可信的东西。教之前，它会先找出高信任度的资源，把它们登记进 `RESOURCES.md`，并在每一课里引用它们。它也是 [stateful](https://www.aihero.dev/ai-coding-dictionary/stateful)（有状态的）。目标、资源、课程，以及你学过什么的记录，都以文件的形式住在这个目录里，所以下一场 session 是从这些文件接着往下走，不是从上次对话残存的东西接着往下走。

## 什么时候找它

要输入 `/teach` 才能调用它，[agent](https://www.aihero.dev/ai-coding-dictionary/agent)（代理）不会自己去找它。

当学习本身就是这个项目的时候用它：一门语言、一个框架、你刚加入的一个代码库、瑜伽、着色器、一个认证考试。它不是用来顺手要一个解释的工具。

| 你想要什么 | 该找谁 |
| --- | --- |
| 花几周学一个主题，一场场 session 累积下来 | `teach` |
| 在你已有的那场 session 里弄懂一个概念 | 就在那场 session 里直接问 |
| agent 最后一条消息没讲通，要它换个说法重讲 | [wait-what](https://aihero.dev/skills-wait-what) |
| 磨利你已有的想法，而不是吸收新材料 | [grill-me](https://aihero.dev/skills-grill-me) |
| 一个后台 agent 去读 [一手来源](https://www.aihero.dev/ai-coding-dictionary/primary-source)，给你留下一份带引用的文档 | [research](https://aihero.dev/skills-research) |
| 学一件在追问中途冒出来的东西，又不想把 [grilling](https://www.aihero.dev/ai-coding-dictionary/grilling)（追问）带偏 | 用 [handoff](https://aihero.dev/skills-handoff) 交出去到一个教学工作区，然后在那里 `teach` |

## 前置条件

`teach` 搭建的是一个目录，而不是产出一个文件，而且这份 Skill 假定一个工作区只服务一个目标，所以要在一个你愿意整个交给单一主题的目录下运行它。别把它放在你正在开发的那个项目里。一个独立的仓库是最好的归宿，比一个全局的 `~/.learnings/` 文件夹或者正在干的项目本身都要好。一个专用仓库还允许你把课程提交进去，团队分享课程走的就是这条路。

会在那个目录里累积起来的东西：

| 路径 | 它装什么 |
| --- | --- |
| `MISSION.md` | 你为什么要学这个。其他每一份文件都依赖它。它要是不存在，`teach` 要做的第一件事就是对你追问到它存在为止 |
| `RESOURCES.md` | 它据以授课的、经过筛选的来源，分成 Knowledge（知识）和 Wisdom（智慧，也就是社群）两部分 |
| `lessons/*.html` | 带编号的课程：教学的基本单位 |
| `reference/*.html` | 压缩过的速查表、算法、术语表：你会反复回来查的那些文档 |
| `learning-records/*.md` | 类似 ADR 的笔记，记录你确实学会了什么，用来决定接下来教什么 |
| `assets/*` | 可复用的组件，首先是一份共享样式表，好让课程看起来像同一门课 |
| `NOTES.md` | 你说出来的教学偏好 |

关于这份清单有两句要补充。术语表对多数主题都合适，但这份 Skill 自带一份 `GLOSSARY-FORMAT.md`，而 `SKILL.md` 已经不再链接到它，所以只有你主动要才会有一份（[issue #559](https://github.com/mattpocock/skills/issues/559)）。这一切都落在你运行 `/teach` 的那个目录里。

## 是储存强度，不是流畅度

值得拿来想一想的那个词是 **储存强度**：长期保持，与 **流畅度** 相对，后者是当下这一次的回忆，读的时候感觉像是掌握了，一周后就没了。`teach` 通过合意困难来建立前者：提取练习、间隔、交错。知识优先。在那个阶段困难对你不利，因为它会占掉你理解所需要的工作记忆。之后 `teach` 会通过一个紧密的反馈回路来训练技能，在那个阶段困难就是工具本身。

两件事决定你会被教什么。**目标**（你想要学会这个的具体现实理由）是每一课的根据。没有它，课程就会变得抽象，而且没有任何东西决定下一步是什么。从目标和学习记录出发，`teach` 在你的 **最近发展区** 里挑出下一课：难到要花时间，但不至于难到学不会。

储存强度也是这份 Skill 会反驳你而不是一味附和的原因。一个需要 **智慧**（现实世界里的判断）的问题，会先得到一个尝试性的回答，然后是一个指向某个社群的指引，让你去那里检验它。这份 Skill 不让你跳过小测。有用户报告说自己说了"多谢啦"，结果被告知练习还没做完。

## 课程、参考文档与组件

一门**课**是一个自成一体的 HTML 文件，短到一次坐下来就能学完，与目标绑定，给出一件看得见的收获。它会引用自己的来源，推荐一份你该自己去读的一手来源，并链接到同级的课程和参考文档。

你很少会回到一门课，但你确实会回到参考文档。所以一门课的压缩形态（那张语法表、那个算法、那套动作顺序、那份术语表）属于 `reference/`，不该埋在第一次讲到它的那门课里。

课程由 `assets/` 里的**组件**搭成：样式表、测验控件、模拟器、图形辅助。复用是默认。agent 在编写一门课之前先读 `assets/`，并用里面已有的东西来搭。任何第二门课也能用得上的新东西，它都写成一个组件，而不是内联。共享样式表是每个工作区里的第一个组件，它让课程看起来像同一门课，而不是一堆互不相干的页面。

## 常见问题

**它把文件放哪了？我的跑到 `~/.claude/skills` 里了。**
放在你运行 `/teach` 的那个目录里（[#377](https://github.com/mattpocock/skills/issues/377)）。

**我待在同一场 session 里，还是每上一课就开一场新的？**
三种做法都行：留在同一场 session、在新 session 里重新调用 `/teach`，或者在同一个文件夹里开一场新 session。每一课就是一次独立的调用。课程状态住在文件夹里，不住在对话里。常见的做法是在工作区里开一场新 session，然后说 `/teach next lesson for <topic>`。

**我怎么知道它没有在教我瞎编的东西？**
光凭这份 Skill 的话，你没法知道。你靠自己读一手来源。`teach` 还不足以让人不加检验地信任，任何建在 LLM 之上的 Skill 都不行。它的接地（`RESOURCES.md`、每一课里的引用、每课一份推荐的一手来源）让检查一堂课的代价很低。但它并没有取消检查这件事的必要性。这个失败真发生过：一个用户在学 2x2 魔方，得到的是一套编出来的转动序列，它根本复原不了魔方。碰上这种情况，检查 model、harness（运行外壳）、effort（推理投入）设置和来源。风险在有精确记号的程序性领域里最高，在输出立刻可验证的地方最低，比如能直接跑起来的代码。

**测验的正确答案永远是第一个选项。**
好几人都确认了这一点，在 Sonnet、Opus 和 GLM 上都是，而且它仍未修复。`SKILL.md` 现在要求每个答案的单词数相同。这消掉了另一条线索（正确答案从前是唯一一个讲清了理由的），但没有动到位置。一位贡献者测过一个在指令层面修位置的办法，正确答案在九门课里仍然是 33 次中有 33 次落在 A 位（[#335](https://github.com/mattpocock/skills/issues/335)）。所以真正的修法是 `assets/` 里一个会打乱答案的测验组件，而不是更好的措辞。在那个东西发布之前，忽略答案的位置。`assets/` 目录归你改，所以你可以要一个在渲染时打乱的组件作为本地补救。

**它假定我已经会某些东西，还用了从没定义过的术语。**
这是最常见那条真实的抱怨。这里没有一个评估步骤。`teach` 从目标和学习记录里推断你的水平，而第一场 session 里没有任何学习记录。一位用户在一条 wayfinder 流水线里跑它，话说得很直白："它从来没做追问来确定我的起点，所以它对我已经会了什么做了一大堆假设。"另一位报告说课程用了没定义的行话，还有一门讲他硬件的课说了那硬件能做什么，却始终没说它做不到什么。两件事能帮忙：在第一条消息里说明你的已有知识和你的缺口；当一堂课估错了水平时，大声把水平纠正过来，因为这次纠正会变成一条学习记录，为下一课引路。一个显式的知识评估步骤是一项长期的功能请求（[#725](https://github.com/mattpocock/skills/issues/725)），不是当前已发布的行为。

**它做间隔重复吗？它知道自己该什么时候停止教吗？**
第一个问题是不做，第二个问题是不可靠。这份 Skill 围绕间隔和交错来设计课程，但没有任何东西安排复习，也没有 Anki 或日历集成。用户经常要这两样。一个相关的缺口是退出标准。正如一位用户所说，`teach` "擅长做出下一课，但不太擅长知道什么时候该停下来、切换到复习或真实练习。"如果你想要的是复习或训练而不是新材料，就开口要；这份 Skill 不会自己提出这个切换。

**它只对代码有用吗？**
不是。被报告得最多的用途在编程之外：韩语、日语的正式语域、钢琴、吉他、桌游设计、OpenSCAD、电影剧情、Azure 和 CCNA 认证、大学考试，还有八岁和十岁的孩子拿到关于密室逃脱和火蝾螈的可打印小书。这份 Skill 里没有任何东西是编程专有的。目标、资源、最近发展区、训练，在任何领域都是同一套走法。在代码里，用户报告的价值最大处是熟悉一个陌生的代码库或一个新团队的技术栈，而不是从零学一门语言。

**我该用哪个 model 来跑它？**
没有标准答案，而被报告出来的差别很大。用户说，[推理投入](https://www.aihero.dev/ai-coding-dictionary/effort) 更高时产出的课程比 medium 档更好。一位用户用 Copilot CLI 配 Codex 跑同一份 Skill，得到一张 30 行的 HTML 卡片，而 Claude Code 产出的是一堂完整的课。它在 Claude Cowork 里可以不做修改地运行，前提是你的组织允许你在那里添加 Skill。如果课程出来很薄，先换 model、换 [harness](https://www.aihero.dev/ai-coding-dictionary/harness) 或换 effort，再考虑重写你的提示词。

## 有效的话应该是这样

- 在一个空目录里，它做的第一件事是问你为什么要学这个，而不是直接产出一堂课。
- `RESOURCES.md` 先于课程被填满，而且每堂课都点名一份值得你自己去读的一手来源。
- 课程里的断言带着指出去的链接。一堂没有引用的课，是这份 Skill 在凭记忆教。
- 一堂课一次坐下来就能学完，而且让你能做到一件以前做不到的事。
- 在文件夹里开一场新 session 说"下一课"，课程是接着往下走，而不是重新开始。
- `learning-records/` 在变多，课程不再重教你已经证明会了的东西。
- 课程看起来像同一门课：它们链接 `assets/` 里的那份样式表，而不是各带各的。
- 一个需要判断的问题，会让你指向一个论坛、一个 subreddit 或一门课，而不只是一个答案。

## 它在整体中的位置

`teach` 是一个**随时可以拿起来用的独立 Skill**。它不是某条构建链上的一步，也不和工程那套流程共享任何产物：它在自己那个目录里工作，持续多久取决于你学这个主题学多久。

它唯一真正的邻居是 [handoff](https://aihero.dev/skills-handoff)。两个合起来回答"我正在被追问一件我不理解的事，该怎么办？"不要停下来去学。`/handoff` 到一个教学工作区，在那里用 `/teach` 学这个主题，然后回去，从你停下的地方接着往下走。旁边还有一个选择是 [research](https://aihero.dev/skills-research)，适合你要的是一份带引用的文档、而不是课程和长期保持的情形。拿不准哪份 Skill 或哪条 flow（流程）合适时，[ask-matt](https://aihero.dev/skills-ask-matt) 在整个这套里给你路由。
