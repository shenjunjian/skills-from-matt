写任何供 agent 消费的文档的参考：一个 Skill，一个 `AGENTS.md` / `CLAUDE.md`，一个由指针指向的文档。包装方式不同，写法相同：让每一个都可预测的是同样那几根杠杆，因为 agent 每次运行的是同一套 _过程_，而不是产出同一个输出。

当你写的文档是一个 Skill，读 [`SKILL-MECHANICS.md`](SKILL-MECHANICS.md)，那里讲 frontmatter、调用方式的选择，以及路由 Skill。

## 上下文指针

**上下文指针**（context pointer）是停在 agent 上下文里的一条引用，它点出一份上下文之外的材料，并把够到它的条件编码在内。Skill 的 description 就是这样一个东西；`AGENTS.md` 里点名某个文档的一行也是同一种对象。决定 agent 何时去够那份材料、以及够得有多稳的，是指针的 _措辞_，不是它的目标。一个非看不可的目标挂在线头无力的指针后面，是一个方差 bug：先把措辞磨利，磨不利才把材料内联进来。

指针干两件事：说清那份材料是什么，再列出应当触发去读它的**分支**（分支就是这份文档要处理的一个个不同情形，于是不同的运行会在文档里走出不同的路径）。一条常驻加载的指针，每个字都在每一轮花钱，所以它比正文更值得狠删：

- **把先行词放到最前面**：指针就是它施展触发的地方。
- **每个分支只留一个触发词。** 给同一个分支换名的同义词，是把一个分支写了两遍；合并它们，只留真正不同的分支。
- **正文已经带上的身份，删掉。**

## 两种负担

你每加一份文档、一条指针，花的都是下面两笔预算之一：

- **上下文负担**是常驻材料占 agent 窗口的代价：一行 `AGENTS.md`、一段 Skill description、任何每轮都待在上下文里的东西，不管触发不触发，都在消耗 token 和注意力。
- **认知负担**是给人的代价：有哪些文档存在、什么时候该去找哪一份。人是那个索引。这不是一笔要压到最低的成本：它是人的自主权的价钱。人的判断要紧的地方就花它，不要紧的地方就把它去掉。

只通过指针才够得到的材料，躲开了上下文负担，代价是指针自己那一行；连指针都没有的材料，整个压在认知负担上。

## 信息层级

一份文档由两种内容构成：**步骤**（agent 依次执行的动作）和**参考材料**（按需查阅的定义、规则、事实）。两者随意搭配：全是步骤（一份菜谱），全是参考材料（一次评审的规则，也就是本 Skill），或者两者都有。核心决策是每一块内容坐在**信息层级**的哪一格上：这是一把梯子，按 agent 需要这份材料有多紧迫来排位。

1. **文内步骤**是第一层：agent 做什么，按什么顺序做。
2. **文内参考材料**按需查阅。它常常是一组正当的平级内容（一次评审的每条规则都在同一格），这是好布局，不是坏味道。
3. **已披露的参考材料**被推到另一个文件里，靠上下文指针够到，只在指针触发时加载。它的跨度从同一目录下的兄弟文件，一直到随处可放、任何文档都能指向的完全外部参考。

往下推得太少，顶上就虚胖；推得太多，就把 agent 真正需要的材料藏了起来。这道张力就是整个决策。

**渐进式披露**（progressive disclosure）就是沿梯子往下走这一步：搬出主文件，藏到指针后面，好让顶端保持易读。它主要不是为了省 token：它是护住层级的办法。分支是最干净的披露测试：每个分支都要的内容留在文内，只有一部分分支会够到的内容推到指针后面。当一份文档里有步骤时，本该披露出去的文内参考材料会把步骤埋掉，让"注意到步骤"变成掷硬币：这是一根方差杠杆，不只是易读性杠杆。

**就近同放**（co-location）是文内的同伴规矩：梯子决定一块内容 _往下坐几层_，就近同放决定它坐下去之后 _旁边是谁_。把一个概念的定义、规则、注意事项放在同一个标题下面，别散落各处，这样读到一处就把它的邻居一起带过来。判据是：这份文档读起来该像一份写给 agent 的文档。归了堆的材料读起来是这样，散落的不是。（跟重复不同：重复是把一个意思写两处；散落是把一个意思剁碎在许多处。）

**蔓生**（sprawl）是这里的失效模式：一份文档纯粹太长，即使每一行都还在用、都不重复。注意力摊在多余内容上就变薄，而且多一行，就多一行需要保持相关。治法是梯子：把参考材料披露到指针后面，再按分支或顺序拆分，让每条路径只带它需要的东西。

## 步骤与完成标准

每个步骤都收在一条**完成标准**上，也就是告诉 agent 活儿干完了的那个条件。两个属性让它成为一根杠杆：

- **清晰度**：agent 能分清做完和没做完吗？一个含糊的边界（"已达成理解"）会招来**过早收工**：步骤还没真做完就收，注意力滑向"已经做完"。前面还看得见的那些步骤（**收工后续步骤**）提供拉力；标准的清晰度就是阻力。按顺序防守：**先磨利边界**（局部、便宜）；只有当它无论如何都含糊 _且_ 你确实观察到那种赶，才把后续步骤藏起来，方法是拆分顺序。藏只在真正的上下文边界上有效（一次交接，或一次 subagent 派发；文内调用会把后续步骤留在上下文里，什么也没清掉）。
- **要求量**：它要求多少。"每个改过的模型都要交代"逼出彻底的活儿，"给出一份改动清单"就不会。要求量驱动**苦功**（agent 在活儿内部做的那些深挖，藏在措辞里，而不是写成单独一步），而且它不绑在步骤上："每条规则都应用"给一堆平级参考材料设了约束，正如"每个步骤都完成"给一条序列设了约束；这就是全是参考材料的文档同样扛得住一条完备性标尺的原因。

最强的标准既能核查又能穷尽。

## 什么时候拆

把一份文档拆成两份，花的是那两种负担之一，所以只在这一刀值回票价时才拆：

- **按顺序拆**：当收工后续步骤诱使 agent 赶眼前这一步时，就在这一串步骤上动刀。让它们离开视野，能逼出更多针对当前任务的苦功。小心反向操作：合并序列会把每个步骤的后续步骤摊到后面内容的目光之下，招来过早收工。
- **按调用方式拆**，是 Skill 专属的：见 [`SKILL-MECHANICS.md`](SKILL-MECHANICS.md)。

## 先行词（leading words）

**先行词**是已经住在模型预训练里的一个紧凑概念，agent 跑文档时就用它来思考（_lesson_、_fog of war_、_tracer bullets_）。它作为一个 token 反复出现，从不作为一个句子出现，于是攒出一份散布在各处的定义，并靠调集模型已有的先验，以最少的 token 锚住一整片行为。自造一个也行，只要你把它定义清楚；但凭空造的词调集不到任何先验：一个预训练词白送的东西，你得拿定义 token 去付账。先去找现成的词。

它锚两次。在正文里锚 _执行_：这个词每出现一次，agent 就伸手去拿同一个行为；在平级参考材料里，它把注意力聚到某一类要找的东西上。在指针里锚 _调用_：当同一个词住在你的 prompt、你的文档和你的代码库里，agent 就把这套共享语言跟那份材料连起来，够得更稳。

到处找用先行词重构的机会。同一个三元组在三个地方各自摊开写，一条指针花一整句去比划一个概念。每一处都在喊"让我塌成一个 token"：

- "快、确定、开销低" → _tight_（一个 _tight_ 循环）。
- "一个你信得过的循环" → _red_，把含糊的门变成可二值观察的状态（循环对这个 bug 要么变 _red_，要么不变）。

你赢两次：token 更少，而且 agent 用来挂思考的钩子更利。假定每份文档都背着几处先行词能够作废的重述。去找出来。

**否定式**是这根杠杆旁边的失效模式：靠禁令来引导，会把被禁的行为拽进上下文，让它 _更_ 容易得手，而不是更不容易。_别去想一头大象_，于是眼前只剩大象；否定是个弱修饰词，被强激活的概念一举冲垮，所以那条禁令有一半读起来像是叫你去做那件事。给出**正面**提示：说出目标行为（"写单行注释"），让被禁的那种行为压根不被提起。一条禁令只有作为你无法正面表述的硬护栏时才站得住；即便如此，也要给它配上正面目标，让注意力落在该做的事上。

## 修剪

- 每个意思只放进一个**唯一事实源**：一处权威之地，于是改行为就是改一处。**重复**（同一个意思出现在多处）花维护的钱，也花 token 的钱，还把一个意思在梯子上的显要程度抬过了它真正的排位。（它是先行词的意外反面：先行词故意重复一个 token，从不重复一个意思。）
- **环境**也是事实源（`package.json` 的 scripts、配置文件、目录布局、`--help` 输出），而重述它的文档就是一份**缓存**：一次查找的副本，只在查找很贵时才值回它的负担。缓存那些 agent 翻了也找不到的东西：没写下来的惯例、某个选择背后的理由、没有哪个配置会交代的那个坑。一个文件一条命令就能查到的，留给环境，在那儿它们不会过期。
- 逐行检查**相关性**：它还对这份文档做的事起作用吗？一行失去相关性有两条途径：从来对任务不起作用（纯粹是讲解，或者一个本该披露出去的分支），或者它描述的行为与世界变了之后它过期了。文档越短，越容易保持相关。没有修剪纪律，默认的结局就是**沉积**：过期的层一层层积下来，因为添加让人安心、删除让人不安，直到你得钻过它们才能找到还在用的东西。
- 逐句搜捕**空转指令**（no-op）：一条模型默认就会遵守的指令，付了负担却什么也没说。判据（它相对默认行为改变行为了吗？）是相对于模型的，不是相对于读者的：两个人对一条空转指令争执不下，争的其实是默认行为，解决办法是把文档跑一遍，而不是辩论。一句不合格，就整句删掉，而不是从里面抠字。这条判据也给先行词打分：一个弱到打不过默认值的词（agent 已经相当细致了，你还说 _be thorough_）就是空转，修法是换一个更强的词（_relentless_），而不是换一种技巧。
