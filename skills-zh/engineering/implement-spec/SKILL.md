你已收到一份 spec（规格说明）。这份 spec 应当带有与之关联的工单，说明如何实现它。

工单系统应当已经提供给你。如果没有，告诉用户运行 `/setup-matt-pocock-skills`。

目标是把整份 spec 在单一一条**集成分支**上实现完毕，并且每个工单都按工单系统关闭工作的方式结案。

工单不是一份步骤清单。它们是一张**任务图**，工单之间有阻塞关系。也就是说，始终存在一批可以随时领走的工单，构成**前沿**。

与 subagent 之间的通信要精简。主要靠**上下文指针**来通信：指向 spec、工单、研究笔记、以及此前的提交。凡是已经能通过指针拿到的信息，不要重复搬运。

**实现 subagent** 尽量放在后台跑，以获得最大并发。

## 步骤

1. 读 spec 和工单，理解这张任务图。

2. （可选）用**探索 subagent**完成工单所需的任何探索，范围包括相关的代码库文件或外部文档。要确保探索 subagent 能存文件：它应把笔记 markdown 存到仓库之外的一个目录里，供后续所有 subagent 访问。这样**实现 subagent**就能专注于实现，而不是探索。

3. 创建集成分支。如果工单系统是通过 PR 关闭工作的，或者用户要求开 PR，那么在第 5 步完成第一次合并之后再开一个草稿 PR（一条没有任何领先 main 的提交的分支开不了 PR），并标注它用于关闭这份 spec 和相关工单。

4. 用**实现 subagent**逐张实现工单，每个 subagent 在自己的 worktree（工作树）里，用自己的分支。每个实现 subagent 要：
   - 开工前确认自己的工作树基于集成分支，不是的话就重置到集成分支上；
   - 调用 Skill 工具，用 `tdd` 构建这张工单；
   - 汇报完成之前，把集成分支的最新提交合并进自己的分支

5. 某个**实现 subagent**做完后，用**合并 subagent**把它的工作合并到集成分支。

6. 如果这改变了可用工单的**前沿**，就再启动若干**实现 subagent**去处理新出现的工单。这样能把并发拉满。

7. 所有工单都完成后，在集成分支上调用 Skill 工具，用 `code-review` 做评审。代码评审提出的问题，交给单个**实现 subagent**一次性修完。

8. 如果存在草稿 PR，把它标记为可评审。否则，按工单系统关闭工作的方式逐张结案，并汇报集成分支。

9. 清理所有**实现 subagent**的工作树。
