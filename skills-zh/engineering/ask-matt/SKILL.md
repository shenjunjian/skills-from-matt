# Ask Matt

你记不住每一个 Skill，所以问。

在说出某个 Skill 做什么、或者建议跳过某一步之前，先读那个 Skill 的 SKILL.md：这里的概述只用于认路。

一条 **flow**（流程）是穿过这些 Skill 的一条路径。大多数路径都沿着一根 **main flow**（主流程）走，另有两条 **on-ramp**（匝道）并进来。其余的要么独立，要么是垫在其他 Skill 底下的一层词汇表。

## 主流程：想法 → 交付

多数工作走的那条路。你有一个想法，想把它做出来。

1. **`/grill-with-docs`** 通过访谈磨清这个想法。只要你是**在一个工作目录里干活**，就从这里起步：它有状态，把学到的东西留在 `GLOSSARY.md` 和 ADR 里。（没有工作目录？改用 `/grill-me`，见下文 Standalone。两者跑的是同一个 `/grilling` 原语；`grill-with-docs` 是会留下书面痕迹的那一个，所以只要有一个仓库可以留下痕迹，它就是两者里更好的那个。）
2. **分支：能光靠对话把所有问题都定下来吗？** 如果某个问题需要一个可运行的答案（状态、业务逻辑、一个你必须亲眼看到的 UI），就绕道去做原型，来回两趟都由 **`/handoff`** 搭桥（原型待在它自己的目录里，这正是 `/handoff` 的用武之地；见"阶段边界"）：
   - **`/handoff`** 出去，然后对着那个文件开一个新会话，
   - **`/prototype`** 用一次性的代码回答那个问题，
   - **`/handoff`** 把你学到的带回来，并在原来那条想法线索里引用它。
3. **分支：这是一个跨多次会话的构建吗？**
   - **是** → **`/to-spec`**（把这条线程变成一份 spec），然后 **`/to-tickets`** 把它拆成 tracer-bullet 工单，每张都声明自己的**阻塞边**。之后用两种方式之一来推进工单：
     - 每张工单跑一次 **`/implement`**，**每张之间用 `/clear` 清掉上下文**。本地跟踪器上就是 `.scratch/<feature>/issues/` 下一张工单一个文件，手工按阻塞优先来做；在真实跟踪器上，这些边变成原生阻塞链接，于是任何一张阻塞项已完成的工单都可以领走。每张工单都自成一体，所以最后一张用完的上下文可以扔掉。
     - **`/implement-spec`** 一趟跑完整份 spec。它把工单读成一张**任务图**，在就绪的 **frontier**（前沿）上并行运行多个 implementer subagent，最后把所有东西落在同一个**集成分支**上。当你宁愿编排整个构建、也不想一张张亲自驱动时，就找它。
   - **否** → 就在**这里**、在同一个上下文窗口里 **`/implement`**。

   无论走哪条，代码都是驱动 **`/tdd`** 做出来的（一次一片 red-green 切片），并用 **`/code-review`** 收尾：对 diff 做一次双轴评审（Standards + Spec）。`/implement` 对每张工单都跑这两样；`/implement-spec` 的各个 implementer 各自驱动 `/tdd`，然后它在集成分支上跑一次 `/code-review`。当你只想用测试先行的方式把某个具体行为建起来、并不想要一份完整 spec 时，单独找 **`/tdd`**；任何时候你想拿一个固定定点去评审某个分支或 PR，单独找 **`/code-review`**。

   活作为 pull request 提上去时，**`/pr`** 负责塑形正文：能展示这次改动的最小视觉呈现、改动可用的前后证据，外加一个单向门还是双向门的判断。它是 model-invoked（模型调用）的，所以 agent 每次写 PR 都会去找它。

4. **`/retro`** 把闭环收上。一次构建之后，尤其是那次不太顺的构建，它回望整场会话，给出对 agent **运行环境**的改动建议，而不是对代码的建议：导航指针、自动化检查、`/code-review` 所执行的编码标准、指引文件、工具链。机械性失误变成确定性检查；靠判断的取舍变成编码标准。下一次构建就从更好的环境起步。

### 上下文卫生

把第 1 到第 3 步保持在**一个不被打断的上下文窗口**里（`/to-tickets` 之前不要压缩也不要清空），这样 grilling、spec 和工单都建立在同一套思考上。之后每次 `/implement` 都从头开始，只照着工单做事。`/retro` 就在它要回望的那个会话里跑，清空之前跑；清空之后，就把它指向那个会话的日志。

这条做法的上限是 **[smart zone](https://www.aihero.dev/ai-coding-dictionary/smart-zone)**：那个窗口（在最先进的模型上约 150k tokens），在这个窗口之内模型还能锐利地推理。如果一场会话在 `/to-tickets` 之前就逼近了它，不要带着退化状态硬推；在最近的阶段边界上 `/compact`，然后接着走（见"阶段边界"）。

## 匝道

一种起始处境：它先产生工作，然后并入主流程。

- **bug 和需求堆成山** → **`/triage`**。它让工单沿着分诊角色往前走，产出能直接交给 agent 做的工单，之后由 **`/implement`** 领走。

  分诊只用于**你自己没创建过**的工单：bug 报告、新来的功能请求、任何裸着到达的东西。`/to-tickets` 产出的工单本来就能直接交给 agent 做，所以**别去分诊它们**。

- **有东西坏了** → **`/diagnosing-bugs`**。给那些难缠的：一眼看不出所以然的 bug、时有时无的 flake、在两个已知良好状态之间悄悄溜进来的回退。它拿到一个**紧凑的反馈循环**（一条命令，已经能针对*这个* bug 变红）之前拒绝空谈，然后带回归测试地把问题修掉。修好之后，在同一次会话里跑 **`/retro`**，问一句什么能提前挡住这个 bug；如果真正的结论是压根没有一个好 seam 能把它锁住，那这活该交给 **`/improve-codebase-architecture`**。

- **一大团雾蒙蒙的工程：一个全新项目，或者一个大到一次会话装不下的功能构建** → **`/wayfinder`**，这里是认知消耗最高的流程。当从此处到目的地的路还看不见时，它在工单跟踪器上绘出一张由 **decision ticket**（决策工单）组成的**共享地图**，一次解决一张，产出的是**决策，不是交付物**，直到雾被推开、路变清晰。**`/grill-with-docs`** 磨的是一个你一次会话装得下的想法，wayfinder 管的是你装不下的那一个，它更慢也更厚重，所以只留给恰好是这种情况的活，绝不用于一个范围清楚的功能。

  地图清楚之后，**它交接，不动手建**：在 **`/to-spec`** 处并入主流程，由它把地图上一堆相互关联的决策收拢成一份可施工的规划，然后照常走 `/to-tickets` 和 `/implement`。把地图直接塞给 `/implement` 会跳过这次收拢，把那些关联细节丢掉；只有当这团活到头来确实很小，才直接去 `/implement`。

## 代码库健康

不是功能开发，只是保养。

- **`/improve-codebase-architecture`** 在你有空闲的时候跑一次，让代码库保持适合 agent 在其中操作。它把**加深机会**摆到台面上；选中一个_就生出一个想法_，你可以带着它从 `/grill-with-docs` 进入主流程。它是找候选项的那次勘测；**`/codebase-design`**（见下）是你设计所选那一个用的工作台。

## 垫在底下的词汇表

两份 model-invoked 的参考，跑在其他 Skill 的*底下*，各自是它那套词汇的唯一事实来源。当问题出在**用词**上而不是流程上时，直接找它们；或者让上面那些 Skill 把它们带进来。

- **`/domain-modeling`**：磨清项目的*领域*语言：质疑一个含糊的术语，解决一个被压了三种含义的词（"account" 在干三份活），把一个难以回退的决策记录成一条 ADR。它是 `/grill-with-docs` 所驱动的那套主动纪律，为的是让 `GLOSSARY.md` 保持一份干净的字词表。
- **`/codebase-design`**：是 deep module 的词汇表（module、interface、depth、seam、adapter、leverage、locality），用来设计一个模块的*形状*：在一个干净的 seam 处，把大量行为藏在一个小接口后面。`/tdd` 和 `/improve-codebase-architecture` 都说这套话。

## 阶段边界

一个 **phase**（阶段）是一次会话里的一大块工作：那次 grilling，那次实现，那次 QA。在两个阶段之间的**边界**上你有五个选项，而在它们之间做选择是整张地图里最模糊的一个决策：

- **Continue**：原地留下。不花钱，不丢东西。
- **`/clear`**：清空窗口，当这里的一切都与下一步无关时。
- **`/handoff`** 写一份可携带的 markdown 文件。适用面很窄：只用于**新的运行环境（harness）**、**新的目录**、一位**同事**，或者在**阶段中途**把一个支线任务 fork 出去。它换来的是可携带性。
- **Subagent**：把一个范围收得很紧的任务送到它自己的窗口，拿回一份报告。
- **`/compact`** 压缩当前上下文，用它给一个全新会话起步。它是**默认选项**，位于决策树底部，而不是首选。

按顺序走的决策树见 [PHASE-BOUNDARIES.md](PHASE-BOUNDARIES.md)：那五个问题、每个分支背后的理由，以及为什么一手来源的代价使得 **Continue** 是第一个该排除掉的选项。这个决策要在边界**上**做；阶段中途，要么继续，要么把剩下的拆成若干 subagent。

## Standalone（独立）

完全在主流程之外。

- **`/grill-me`**：和 `/grill-with-docs` 一样不依不饶的访谈，但**无状态**：它不在本地保存任何东西，也不建 `GLOSSARY.md`。当你**不在一个工作目录里干活**时用它（磨一份计划、一个设计、一篇文章，任何底下没有仓库的东西）。如果你在一个工作目录里，就用 `/grill-with-docs`：它跑同一套访谈，还会留下书面痕迹，所以它严格来说更好。
- **`/grilling`** 就是访谈原语本身：一轮一轮、frontier、查证事实是 agent 的活，做决策是你的活。`/grill-me` 和 `/grill-with-docs` 是两个具名的入口，`/triage`、`/wayfinder` 和 `/improve-codebase-architecture` 内部都在跑它。只有当你想要这套访谈、外面不套任何东西时，才直接找它。
- **`/prototype`** 是一个小巧的、用完就扔的程序，回答一个设计问题：这个状态模型对不对，或者这个 UI 该长什么样。"用完就扔"是对代码怎么写的一个约束，不是把它销毁的承诺：答案折进真正的代码里，原型本身留在 `prototype/<name>` 分支上、远离 main，作为一份 **primary source**，并在实现工单里指向它。它是主流程第 2 步里的那次绕道，但任何设计上纸上定不下来的问题，随时可以找它。
- **`/research`**：把跑腿的查阅工作交给一个**后台 agent**：它针对**一手来源**调查一个问题，然后在仓库里留下一个带引用的 Markdown 文件。它读的时候你继续干活。它产出的那份文件是该*带进*主流程、从 `/grill-with-docs` 入场的东西，因为 research 是喂给思考，不是替代思考。
- **`/to-questionnaire`** 在你被卡住的地方不在你脑子里、也不在代码库里，而在**别人**脑子里时登场，它给对方写一份问卷去填。它是 `/grill-me` 的反面：不访谈你关于那个主题，而是访谈你关于这次**发送**（要发给谁、你需要拿回什么），并把问题对着那个缺口瞄准。拿回来的东西是喂给 `/grill-with-docs` 或 `/to-spec` 的原料。
- **`/wizard`** 管的是只有**人**能走的步骤：开通基础设施、配置凭据或 CI 密钥、在陌生的第三方控制台里点来点去、跑一次性的迁移或切换。它生成一个交互式 bash 脚本，逐个打开 URL、逐个取值、写进 `.env` 和 GitHub secrets，于是这套流程不再需要你每次重新给 agent 讲一遍。它是 model-invoked 的，所以 agent 一撞上只有你能过的那堵墙就去找它。如果 agent 自己就能做，它就该自己做；这套是给确实需要人在回路里的地方用的。
- **`/wait-what`** 是给一条没落地的消息做的补救。在对话中途、在任何其他 Skill 里面用它，agent 会带上你之前缺的那块上下文，用平实的话、用 `GLOSSARY.md` 的词汇，把它刚说的东西重新讲一遍。它事后起作用；`/grill-with-docs` 是事前那剂预防针，因为早点谈定的共享语言才是让黑话压根不发生的原因。
- **`/teach`**：跨多次会话学一个概念，把当前目录当作有状态的工作区。
- **`/writing-for-agents`** 是撰写 agent 消费的文档时的参考：Skill、AGENTS.md、被指针指向的文档。

## 前置条件

**`/setup-matt-pocock-skills`**：在你第一次跑 engineering 流程之前运行它，用来配置其他 Skill 所依赖的工单跟踪器、分诊标签和文档布局。自定义的工单跟踪器也一样能用。
