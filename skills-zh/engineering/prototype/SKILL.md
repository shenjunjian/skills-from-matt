# Prototype（原型）

原型是**回答一个问题的用完即弃的代码**。问题决定形状。

## 选一个分支

判断当前在回答哪个问题，依据可以是用户的提示词、周围的代码，用户在场就直接问一句：

- **"这套逻辑 / 状态模型对不对？"** → [LOGIC.md](LOGIC.md)。构建一个单文件的可分享 HTML（自由操作按钮加标签页式的引导走查），把状态机推过那些纸面上难以推理、且非开发者也能上手驱动的用例。
- **"这该长什么样？"** → [UI.md](UI.md)。在同一条路由上生成几个截然不同的 UI 变体，通过 URL 查询参数和一个悬浮底栏切换。

两个分支产出的东西差别很大，选错就把整个原型浪费了。问题确实含糊又找不到用户时，默认选跟周围代码更吻合的那一支（后端模块走逻辑；页面或组件走 UI），并把这条假设写在原型开头。

## 两个分支都适用的规则

1. **从第一天起就是用完即弃的，并且明确标出来。**原型代码放在它实际要服务的位置附近（贴着它为之做原型的那个模块或页面），这样上下文一目了然；但命名要让随手一读的人看得出这是原型，不是生产代码。为一次性路由做 UI 原型时，沿用项目本来就在用的路由约定；不要另造一套顶层结构。
2. **跑起来毫无门槛。**UI 原型从项目任务运行器里的一条命令起步：`pnpm <name>`、`python <path>`、`bun <path>` 之类。逻辑演示是一个让用户双击的 HTML 文件。无论哪种，启动它都不必动脑子。
3. **默认不做持久化。**状态存在内存里。持久化是原型要_考察_的对象，不是它所依赖的东西。问题确实涉及数据库时，用一个临时库或一个本地文件，名字取得明明白白："PROTOTYPE, wipe me"。
4. **不用打磨。**不写测试，错误处理只做能让原型_跑得起来_的那部分，不做抽象。目的是尽快学到东西。
5. **把状态亮出来。**每次 action 之后（逻辑）或每次切换变体之后（UI），打印或渲染完整的相关状态，让用户看得见改了什么。
6. **做完就把它收下来。**凡是经过验证的决策，折进真实代码；然后把原型本身作为一份**一手素材**收下来：提交到一个一次性分支，离开 main，并在实现工单上留一个指向该分支的上下文指针。答案也一并记下（结论，以及它敲定了哪个问题），写进工单或提交信息。main 分支只保留经过验证的那个决策。
